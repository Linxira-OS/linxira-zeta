# Requirements Ledger

This file is Zeta's durable answer to **"what must still ship, and what proves it?"**
It is the canonical register of requirements. Chat history, todo lists, and audit
reports are inputs; they are not the register.

- **ADR** (`document/adr/`) records **why** a contract decision was made.
- **This ledger** records **what** was asked, **where** it stands, and **what evidence**
  exists.
- **Code, tests, and runtime docs** remain the source of truth for current behavior.

Every user request enters this ledger before work starts, including requests that
are only mentioned in passing. The intake, WIP, delegation, verification, and
release rules live in
[`document/agents/workflow/execution-contract.md`](agents/workflow/execution-contract.md).

## Status vocabulary

Only these statuses are valid. `scripts/check-requirements-ledger.ts` enforces the
vocabulary and the evidence rules below.

| Status        | Meaning                                                                                                         |
| ------------- | --------------------------------------------------------------------------------------------------------------- |
| `INBOX`       | Captured verbatim from a user request. Not yet judged, split, or accepted.                                      |
| `TRIAGED`     | Real work, but scope and acceptance are not settled. A lane is assigned.                                        |
| `SCOPED`      | Scope, acceptance criteria, files, dependencies, and evidence plan are written. Work may start.                 |
| `IN_PROGRESS` | Someone is actively working it. A worker brief exists and names the REQ ID.                                      |
| `IMPLEMENTED` | The change exists in the tree or a PR. **Not** proof that it works.                                              |
| `VERIFIED`    | An independent verifier read the changed files and ran the named checks. Evidence is recorded.                  |
| `RELEASED`    | The verified change is in a shipped release or tag. Release evidence is recorded.                               |
| `DEFERRED`    | Deliberately not shipping now. Requires an explicit approval record and a re-entry trigger.                      |
| `BLOCKED`     | Cannot proceed. The exact blocker and what was tried are recorded. Never use it as a synonym for "not started". |

Status is not transitive: mentioned ≠ scoped, scoped ≠ in progress, in progress ≠
verified, verified ≠ released.

## Evidence rules

- Evidence is a durable pointer: changed file paths, test names and the command
  that ran them, CI run IDs, PR numbers, release tags, or ADR IDs.
- Chat claims, agent self-reports, and "I ran it locally" are not evidence.
- `IMPLEMENTED` requires a file/commit/PR pointer.
- `VERIFIED` requires a verification pointer (`test`, `check`, `CI`, `PR #`, or
  `bun run`).
- `RELEASED` requires a release/tag pointer.
- A `local://` audit is acceptable as analysis provenance, but it is session-scoped
  and may not survive. Durable code paths and tests in the audit must be cited too.
- **No requirement is marked done without evidence.** If evidence is missing, the
  status stays where the evidence ends.

## Deferred and blocked records

A `DEFERRED` row must say who approved the deferral and what would re-open it.
A `BLOCKED` row must state the exact external blocker and what was tried. If that
information is missing, the row is not really deferred or blocked; move it back
to `TRIAGED`.

## Updating the ledger

1. Append new requests as `INBOX` with the next free ID. Never renumber or reuse
   an ID; retire a row by changing its status, not by deleting it.
2. Move a row forward only when the destination status's evidence requirement is
   satisfied.
3. When work switches, record `IN_PROGRESS`, the WIP reason, and the resume
   condition in the row's Remaining column.
4. Run `bun run check:reqs` after edits. The guard is structural; reviewers still
   judge whether the evidence is honest.
5. Keep this file and the execution contract in sync. A policy change that is not
   reflected in both is incomplete.
